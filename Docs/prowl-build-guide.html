Prowl: What to Build and How

A local browser daemon plus thin CLI that lets any agent, vision or not, operate websites cheaply and safely. Logged-in sessions whose secrets the model never reads. Compact token-budgeted output. Guaranteed cleanup of every browser it starts.

00Decision: build from scratch

Build your own daemon and CLI on Playwright core behind a BrowserBackend interface. Use agent-browser and Playwright MCP only as M0 bake-off baselines, not as the foundation.

Why scratch wins PRO

  • Prowl value is the surrounding layer: leases, secret refs, domain profiles, ladder, tier budgets, verified memory.
  • Those tools cover snapshot plus act only, the least differentiated slice.
  • You keep the backend abstraction and process ownership needed for M2 and M6.

Why layering loses CON

  • Subprocess driving plus output re-parsing: brittle and verbose.
  • Verbose output breaks token budgets at every step.
  • Single backend collapses the stealth abstraction.
  • No leases, no secret refs, no process-group cleanup.

Borrow conventions (ref format eN, observe-after-act), not the process. Flip only if M0 shows a massive gap plus a library API, multi-backend support, and leases.

01Users, in build order

  1. Test your own web app with a logged-in profile. Build for this first.
  2. Operate third-party apps you hold accounts on and have permission to automate.
  3. Read JS-heavy or gated pages where plain HTTP fetch fails.
  4. Harder public pages via pluggable stealth backends. Optional, last.

02Architecture

Agent or script calls the thin prowl client, which speaks JSON-RPC 2.0 over a Unix socket (named pipe on Windows, user-only permissions) to prowld, one daemon per user. CLI calls are short-lived; browsers persist in the daemon between commands. Auto-starts on first use, exits after 15 idle minutes with zero sessions. Nothing listens on a network port.

04Roadmap M0 to M7

  1. M0: Bake-off

    1 to 2 days · DECISION GATE · you are here

    Three fixture tasks times three helpers (agent-browser, Playwright MCP, Prowl proto). Measure bytes, steps, success, time. Deliverable: DECISION_M0.md. Stop for human approval.

  2. M1: Core daemon, sessions, snapshot and refs, actions

    core engine
    • open to snapshot to click ref to snapshot diff to close works
    • Envelope plus exit codes match for success and every reachable error
    • Stale refs return STALE_REF or silently re-resolve
    • Iframe, shadow DOM, dialog, upload and download fixtures pass
    • Warm click and snapshot p50 under 300 ms; Tier-3 step under 8,000 bytes

  3. M2: Lifecycle and cleanup

    core engine

    Idle TTL 10m, max lifetime 2h, owner-death grace 60s, orphan sweep, per-session FIFO, PROFILE_LOCKED and SESSION_BUSY. Leak test: 100 runs with random kill -9, zero leftover browsers and profiles.

  4. M3: Profiles and auth

    trust and safety

    Pre-authed profile, cookie import, headed login handoff. Auth canary plus AUTH_REQUIRED. Allowed-domains enforced. Eval denied by default. Scrubber plus canary-grep with zero hits. Audit log. Handoff and resume.

  5. M4: Fetch, ladder, extraction, memory

    trust and safety

    fetch and read with escalation trace and hard caps. Extraction quality at least 90 percent on a 30-page corpus. Hidden-content stripping plus injection warnings. Verified memory with TTL and forget.

  6. M5: Tiers, plan runner, MCP, agent guide

    scale to agents

    Tier byte defaults. Tier-3 never needs screenshots. Plan runner stops at first failure with per-step envelopes. MCP generated from zod. Guide validated by a real run.

  7. M6: Stealth backends plus detection

    scale to agents · timeboxed

    Challenge detector at least 90 percent precision. Two extra backends pass conformance. L3 and L4 escalation with hard abort. No custom fingerprint engine, no solvers.

  8. M7: Hardening plus packaging

    ship hardening

    API-token injection plus scripted login with secret and totp refs. Encrypt-at-rest for medium-risk profiles and up. npm package. Windows pipe verified.

05Escalation ladder

prowl read climbs one rung at a time, cheapest first, with 1 attempt plus 1 retry per level then a hard abort with a reason trace. Default max level is 2; levels 3 and 4 need an explicit flag.

L0 fetchundici, no JS, markdown out
›
L1 browserephemeral, default backend
›
L2 profilepersistent, authenticated; default max
›
L3 stealthalternate backend, explicit flag
›
L4 humanhandoff, operator solves

Escalate on: empty body, enable-JavaScript shell, challenge detected, 401 or 403. Start at L2 when a profile is given. Documents return DOCUMENT_DETECTED with a path, never parsed inline.

Secrets never as plain args: stdin, env ref, file ref, or keychain ref only. Refs look like e4 and go stale after navigation; on STALE_REF re-snapshot and retry.

08Lifecycle essentials

  • Owner resolves from flag, env, else nearest non-shell ancestor PID. Owner death gives 60s grace, then close.
  • Ephemeral profile dirs wiped on close and at daemon start. Kill -9 must still converge to zero orphans.

09Auth essentials

Protects against: model reading plaintext creds from output, logs, or memory; creds persisting where agents can read them; injected pages steering the session off-domain. Does not stop an authorized agent from acting as the user inside allowed domains. A logged-in profile is a capability; scoping plus confirmations plus audit only reduce risk.

ModeNameNotes
0API tokenheader template, daemon injects
1Pre-authed profilehuman logs in once; default recommendation
2Cookie importimport file, check expiry
3Login handoffheaded browser, human handles MFA
4Scripted loginsecret and totp refs; last resort, M7
  • Profiles require allowed_domains; offsite nav including redirect hops returns POLICY_DENIED.
  • Scrubber runs on every envelope, artifact, log, memory write, and audit entry. Cookie values never returned.
  • Destructive or financial actions return CONFIRMATION_REQUIRED unless flagged and policy allows.

11Explicitly not building (v1)

  • Custom fingerprint-spoofing engine; CAPTCHA solvers; proxy networks (user supplies).
  • Self-hosting Firecrawl or doc converters as dependencies (adapter hooks only).
  • GUI, cloud hosting, multi-user operation; bypassing auth, paywalls, or access controls.
